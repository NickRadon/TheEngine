# Testing and remote review

- The user reviews this project remotely. When running an engine test, capture its visual result and include the screenshot in the chat response. Local file images have not rendered for this user: for AK animation work, run `tools/Test-AkAnimation.ps1`, commit and push its updated `docs/test-captures/ak/latest-*.png`, and include HTTPS GitHub image links for both views in chat, along with the test result and relevant grip metrics. If a check cannot produce a screenshot, say so plainly.
- `tools/Test-AkAnimation.ps1` runs only the animation self-tests. It uses `Assets/AE` from AE Master or `-AeAssets`, writes logs and metrics under `build/test-captures/ak`, and copies review PNGs to `docs/test-captures/ak`. It imports temporary copies; do not write generated materials beside the Unity source FBXs.
- When the project MCP bridge is available, use `read_ak_state` for the current rig/report, `set_ak_weapon_rotation` for a validated AK offset edit, and `run_ak_animation_test` for the capture loop. The bridge is scoped to this repo; see `tools/mcp/README.md`. Still commit and push refreshed review PNGs before sharing GitHub links remotely.
- Keep unrelated working-tree changes intact. Do not modify the separate `AnimationSetup` playtest project.
