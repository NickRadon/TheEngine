# Animation Controller pose graph direction

The AK controller uses two pose sources: locomotion for `root`, `pelvis`, and legs; the AK first-person clip for `spine_01` and every descendant. The gun and both hand IK markers are separate skeleton branches, so the upper layer explicitly includes `ik_hand_gun`, `ik_hand_l`, and `ik_hand_r`. At mask boundaries, the spine keeps pelvis translation but takes the FP model-space rotation. IK markers take the FP model-space position and rotation so walking hips cannot move their targets. Rig operations then run in order: copy the authored weapon marker, apply the weapon rotation offset, copy authored hand targets, apply spine/head look, and solve the arms.

The immediate authoring path is in the Animator layer panel: **Use spine_01 upper body + weapon IK** writes those four roots into the controller's own layer mask. The `.mask` asset remains optional for sharing a mask. **Edit Rig Graph** opens the active character's rig from the controller, but the existing rig graph is still a separate serialized asset and editor.

The intended next editor model follows Godot's [AnimationTree blend graph](https://docs.godotengine.org/en/stable/tutorials/animation/animation_tree.html): one controller graph with typed pose pins and a required Output node. An AK graph would be `Locomotion → Layered Blend (lower input)`, `FP AK Idle → Layered Blend (upper input)`, then `Copy Gun Marker → Weapon Offset → Copy Grip Targets → Look → Two Bone IK L/R → Output`. The layered blend node owns a bone filter edited through a searchable skeleton tree; `spine_01` shows its descendants, and the three IK markers are checked explicitly. A node inspector exposes named transform and weight fields, not serialized numeric slots. The graph should save node IDs, positions, connections, and parameters in the `.controller`; execution should topologically evaluate the same pose stream used by the current controller and rig operations. Cycle and missing-bone validation must run before saving. This replaces the current rig line editor only after controller serialization and runtime evaluation support the same node order, so the AK graph does not silently lose its weapon offset or grip constraints.
